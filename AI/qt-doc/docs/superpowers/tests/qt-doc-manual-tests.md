# qt-doc Skill 手动测试用例

- 日期：2026-08-05
- 关联功能：Qt 专家模式（显式开启触发，会话级隔离）
- 类型：交互测试（需在 opencode 会话中手动验证）

## 测试环境准备

1. 重启 opencode（让最新 SKILL.md 生效）。
2. 准备两个会话：**会话 A**（新开）、**会话 B**（新开）。

## A. 触发正确性（该触发时必须触发）

| # | 输入 | 预期 | 验收 |
|---|---|---|---|
| A1 | `开启Qt专家模式` | 加载 qt-doc，AI 确认进入专家模式 | 看到 `→Skill "qt-doc"` |
| A2 | `进入Qt专家模式` | 同上 | 同上 |
| A3 | `Qt专家模式` | 同上 | 同上 |
| A4 | `开启 Qt 专家模式`（带空格/中英文混合） | 同上 | 同上 |

## B. 零误触发（不该触发绝不触发）

| # | 输入 | 预期 | 验收 |
|---|---|---|---|
| B1 | `查一下 QTcpSocket 怎么用`（未开启模式） | **不**触发 qt-doc，普通回答 | 无 `→Skill` |
| B2 | `Java 里线程和进程的区别` | 不触发，正常答 Java | 无 `→Skill` |
| B3 | `React 里定时器怎么用` | 不触发，正常答 Web | 无 `→Skill` |
| B4 | `Python 的 list 和 tuple 区别` | 不触发 | 无 `→Skill` |
| B5 | `什么是线程池`（未指定 Qt） | 不触发，通用回答 | 无 `→Skill` |
| B6 | `用 Qt 写个界面`（提到 Qt 但没说开启模式） | 不触发 | 无 `→Skill` |

> B6 是关键：**提到 Qt 但不触发**，验证"仅开启词"的严格性。

## C. 会话内持续生效（开启后一路走 Qt 流程）

| # | 输入 | 预期 |
|---|---|---|
| C1 | 开启后：`查一下线程怎么用` | 触发 qt-doc，映射为 QThread，走抓取流程 |
| C2 | 开启后：`QTimer 和信号槽怎么配合` | 直接走 Qt 文档流程（无需再开） |
| C3 | 开启后：`窗口布局用什么类` | 走流程，输出 QLayout 等 |
| C4 | 开启后：`Java 的 HashMap 原理` | **正常答 Java**，不套 Qt 流程（专家模式下仍分清领域） |

## D. 会话隔离

| # | 操作 | 预期 |
|---|---|---|
| D1 | 会话 A 开启专家模式 → `/sessions` 恢复 A | 专家模式**仍生效**，说`查一下线程`走流程 |
| D2 | 会话 A 开启后 → 新开会话 B | B 中 `查一下线程怎么用` **不触发**（未开启） |
| D3 | 会话 B 中 `开启Qt专家模式` | 独立触发，与 A 互不影响 |

## E. 输出质量（专家模式下）

| # | 输入 | 预期 |
|---|---|---|
| E1 | `查一下 QTcpSocket 怎么用` | 继承链展开、inheritsFrom 标注、异步示例先等 connected() |
| E2 | `查一个不存在的类 QFakeClass` | 明确报错提示拼写/模块，不编造 |
| E3 | `查一下定时器怎么用` | 映射 QTimer，识别 timeout() 信号 |
| E4 | `查一下线程和定时器怎么配合` | 一次抓取多个类，说明协作用法 |

## 建议执行顺序

1. 先跑 **B1-B6**（零误触发）——改造的核心验收。
2. 再跑 **A1-A4 + C1**（触发与生效）。
3. 最后 **D1-D3**（隔离）+ **E1-E4**（质量回归）。

## 回归判断标准

- **通过**：B1-B6 全部不触发；A1-A4 至少 1 种写法触发；C/D 符合预期；E 无严重错误。
- **失败信号**：B6（提到 Qt 但不触发）失败 → description 匹配有残留，需再收紧触发词。
- 若 A1-A4 全部不触发 → 说明 skill 未被识别，检查安装路径与 frontmatter。
