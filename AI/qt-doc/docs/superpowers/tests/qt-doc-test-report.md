## 三、关键发现与优化建议

### 发现的机制性要点

1. **会话内生效 ≠ 重复加载 skill**。恢复会话后模型不会再次调用 `tool=skill`,而是基于会话记忆直接以 `[qt-doc]` 前缀走 Qt 流程。测试判定需用三信号(再次加载 skill / 调用 `qt_fetch.py` / 输出 `[qt-doc]` 前缀),单纯检测 skill 加载会误判——本脚本已修正。

2. **`opencode run -s <sessionID>` 可自动化会话延续测试**,是 D1/C 类可脚本化的基础。

### 建议(非阻塞)

| 优先级 | 建议 |
|---|---|
| 中 | 为增加稳定性,可在 skill description 中加"仅当你明确说出‘开启Qt专家模式’等词时才触发"的更强否定式表述,降低偶发误触发概率 |
| 低 | E 类质量关键词匹配目前为启发式正则,若需更严格可改为结构化断言(如校验 JSON 事件中存在 bash 调用 `qt_fetch.py` 且成功) |
| 低 | 全量测试约 6-8 分钟,日常回归可用 `-SkipE` 快速跑 A-D |
