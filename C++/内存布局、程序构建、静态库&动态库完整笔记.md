## 一、程序构建阶段确定内存段（Build‑time 构建时确定布局）

> Determined at Build Time：`.text` / `.rodata` / `.data` / `.bss` 的内存布局、大小在编译链接构建阶段就确定，不是程序跑起来才决定。 这几段都属于**static lifetime 静态生命周期**，由编译器自动管理分配与释放，程序员不能手动干预申请释放。

### 1. .text 代码段（文本段）

- 存储内容：编译之后的机器指令（机器码 machine Code），就是我们写的函数、if/for循环、main函数等翻译成CPU能执行的指令。
- 大小：Fixed size，构建阶段确定大小。
- 权限：Read‑only **只读**，防止运行时篡改程序指令。
- 生命周期：静态生命周期，进程整个运行期间都存在，进程退出由操作系统回收。
- 管理：完全由编译器、链接器自动管理，程序员没有API手动分配释放本段内存。

### 2. .rodata 只读数据段（read‑only data）

- 存储内容：初始化后的常量，比如字符串字面量`"hello world"`、`const char *p = "abc"`这类常量字符串；全局const常量。

- 权限：只读 Read‑only，程序运行不能修改，写操作会触发段错误。

  > 区分：`const int a =10;` 全局的放rodata；局部const变量本质还是栈上。

### 3. .data 数据段（Non‑zero initialized statics / globals）

- 存放：**非0初始化的全局变量、静态static变量**

```
int g_a = 100;   // 存放在 .data
static int s_b = 20; // 存放在 .data
```

- 读写权限：Read / write 可读可写，运行时可以修改变量值。

- 时机：变量大小在编译链接构建阶段确定，程序运行时直接可用。

  > 只针对**有初始值且不是0**的全局、static静态变量。

### 4. .bss 段（Uninitialized statics / globals）

- 存放：未初始化全局变量、未初始化static静态局部变量

```
int g_c;       // .bss
static int s_d;// .bss
```

- 特性：**Zero‑initialized**。可执行文件磁盘上不占用实际存储，程序加载到内存的时候操作系统自动把这一块全部清零。

- 读写权限：可读可写。

  > 磁盘exe体积不会把bss的空间算进去，加载进内存才开辟对应内存并置0。

### 5. stack 栈内存

- 存储内容：函数内部局部变量、函数形参、函数返回地址、函数调用帧，遵循**后进先出 LIFO**。
- 大小：Fixed size，固定大小，操作系统给每个进程栈设置上限。
- 读写权限：可读可写。
- 分配释放：**编译器自动管理**，函数进入自动压栈分配，函数退出自动弹栈回收。程序员不能手动malloc/free栈。
- ⚠️递归坑：递归调用**必须要有终止终点条件**，否则无限递归不断往栈压入栈帧，栈空间耗尽 → **Stack overflow 栈溢出**程序直接崩溃。
- 现代系统特性：栈会做保护机制，以**空间换取安全性，降低程序出错的复杂度**。

### 6. heap 堆内存

- C语言：`malloc()` / `free()`
- C++语言：`new` / `delete`
- 存储：程序员手动申请的动态内存。
- 分配释放：**完全由程序员手动管理**，申请后不free会内存泄漏；free多次会堆破坏。
- 大小：灵活，没有栈那样的硬性固定上限（受操作系统总内存限制）。
- 读写权限：可读可写。

> 现代32位操作系统：ASLR地址随机化，同一个可执行程序**每一次运行，加载到虚拟内存的位置都不一样**，用来对抗漏洞攻击。

## 二、C/C++程序完整生命周期：构建阶段 + 加载运行阶段

整体流程：源码文件 → 预处理 → 编译 → 汇编 → 链接（生成可执行exe / 库）→ 操作系统加载器Loader加载程序进内存 → 运行main函数。

### 阶段① 预处理 preprocess

作用：处理`#include`头文件、**宏替换展开**，删除注释。 输入：`.c / .cpp`源码 输出：预处理后的文本文件。

示例命令示意：

```
gcc -E main.c -o main.i
```

### 阶段② 编译（狭义编译）

把预处理后的C/C++源码翻译成汇编代码。 输入：预处理文件 输出：`.s`汇编文件。

```
gcc -S main.c -o main.s
```

### 阶段③ 汇编 assemble

将汇编`.s`翻译成机器码，生成目标文件`.o`（Linux）/`.obj`（Windows）

> 重点笔记原文：**汇编阶段不会做业务逻辑错误检查**，只检查汇编语法。C语言逻辑错误在这里不会报错。

```
gcc -c main.c -o main.o
```

多文件同时编译出多个目标文件：

```
gcc -c myadd.cpp mymultiply.cpp main.cpp
# 输出 myadd.o  mymultiply.o main.o
```

### 阶段④ 链接 link

输入：一堆`.o`目标文件 + 库文件（静态库 /动态库） 输出：可执行程序（Linux ELF可执行、Windows exe）或者新库。

链接的工作：

1. 合并各个`.o`的各个段（text、rodata、data、bss）
2. 符号解析，找到函数调用对应的函数定义
3. 符号重定位，把相对地址改成虚拟内存地址

> 链接有依赖顺序：A库依赖B库，则顺序要注意；这个依赖顺序会受编译器优化选项影响。

## 三、静态库（Static Library）

Linux后缀：`.a`；Windows静态库：`.lib` 本质：把很多`.o`目标文件打包归档成一个文件，**不是可执行文件**。

### 1. 创建静态库

使用`ar`归档工具打包：

```
ar rcs libmymath.a myadd.o mymultiply.o
```

- `r`：插入替换模块
- `c` 创建库
- `s`生成索引，加速链接

### 2. 使用静态库链接生成程序

```
gcc main.o -L. -lmymath -o program
```

- `-L.`：告诉链接器，**在当前目录搜索库文件**
- `-lmymath` 代表链接`libmymath.a`

### 3. 静态库核心特点

1. **链接阶段直接把库里面的目标代码拷贝复制进最终可执行程序**。
2. 可执行程序体积会变大，库代码被打包进exe。
3. 生成静态库之后，原始`.cpp`源码可以直接删除，只保留`.a`库即可编译链接。
4. 程序运行的时候不再依赖原来静态库文件，exe自身已经包含全部机器码。
5. 多个程序使用同一个静态库，每个程序文件内部都会存一份库副本，磁盘占用会重复。

## 四、动态库 / 共享库 Shared Library

Linux：`.so`；MacOS：`.dylib`；Windows：`.dll`

### 1. 编译生成动态库

编译目标文件需要位置无关代码，生成共享库：

```
# 生成动态库
gcc -shared -o libmymath.dylib myadd.o mymultiply.o
# 链接可执行文件
gcc main.o -L. -lmymath -o my-program
```

### 2. 链接阶段发生什么

> 重点：**链接的时候不会把动态库机器码拷贝进可执行文件**。 可执行程序内部仅仅写入标记、符号表，记录“运行时需要加载哪个动态库”。

真正加载、符号解析工作，**不在链接阶段，而是推迟到程序运行的时候**。 操作系统的`Loader`加载器，读取exe内标记，找到磁盘上的动态库文件，加载进进程虚拟内存，解析符号地址，完成函数调用绑定。

- 动态库特性1：内存中可以做到多进程**共享同一份动态库代码段**，节省物理内存。
- 动态库特性2：动态库运行加载时，可以映射到虚拟内存任意地址（配合ASLR）。
- 运行依赖：运行环境必须存在对应动态库文件，如果丢失dll/so/dylib，程序直接启动失败。

## 五、静态库 vs 动态库对比总结

| 项目             | 静态库 `.a`/`.lib`        | 动态库 `.so`/`.dll`/`.dylib`        |
| ---------------- | ------------------------- | ----------------------------------- |
| 库代码拷贝时机   | **链接阶段拷贝代码进exe** | 链接阶段只写标记；**运行时加载库**  |
| 可执行文件大小   | 体积大，内置库代码        | 体积小，不含库机器码                |
| 运行时依赖库文件 | 不需要，exe自给自足       | 必须要有对应库文件，缺失无法启动    |
| 内存多进程       | 每个进程有独立副本        | 多个进程共享内存中同一份库代码      |
| 更新库           | 重新链接整个程序          | 替换动态库文件即可，不需要重编译exe |

## 六、易错点汇总（来自原始笔记）

1. 栈大小固定，递归无终止条件直接栈溢出 Stack overflow。
2. `.bss`段磁盘文件不占大小，加载进内存操作系统才清零。
3. 汇编只检查汇编语法错误，C语言业务逻辑错误汇编不会报错。
4. 静态库链接存在库依赖顺序，编译器优化会改变链接行为。
5. rodata存放常量字符串，运行写rodata内存直接段错误崩溃。
6. 动态库真正解析符号是程序运行阶段，不是gcc链接那一步。
7. ASLR地址随机化：同一个程序每次运行虚拟地址都不一样。
8. text、rodata、data、bss全部构建阶段确定布局；栈堆是运行时分配内存。
